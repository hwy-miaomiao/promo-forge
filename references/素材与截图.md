# 素材与截图

> **什么时候读这一篇**：**阶段 4 素材调研与真实截图** 时读。做样帧（阶段 2）需要真实界面时也先读第 2 节。

## 1. 一手素材优先级

固定优先级，**不许跳级**：

**用户提供的一手素材 > 真实页面截图（本仓库脚本截） > AI 生成图 > 网络图片**

- 功能展示**必须是**真实界面截图或真实作品图。AI 图只能做包装、转场、背景。
- 硬性配额：**每个功能段落至少 1 张真实截图**；**片长 ≤45 秒时全片真实素材 ≥6 张，>45 秒 ≥8 张**；必须有**一段由 ≥6 张真实作品组成的快切蒙太奇**。
- 数量不够就回去补素材，**不要用 AI 图凑数**。凑数的表现很明确：蒙太奇里出现两张质感不同的图，观众一眼看出是拼的。
- 每张用到的图都要记进 `调研笔记.md`（来源 + 授权），见第 7 节。

## 2. `capture.py`：真实网页截图

Playwright 驱动真实浏览器截图，**默认 2 倍图**。禁止用 AI 工具自带浏览器的截图功能——它们通常只有 1 倍分辨率，放进 1080 宽的竖屏视频就是糊的。

```bash
python scripts/capture.py <url> <name> [--factor 2] [--at 0,900,1800] [--full 3600] \
                          [--device iphone] [--hide 选择器] [--login] [--out out/shots]
```

| 参数 | 含义 | 典型用法 |
| --- | --- | --- |
| `<url>` `<name>` | 目标地址、输出文件名（不含扩展名） | `https://acme.com/dashboard dashboard` |
| `--factor 2` | 输出像素密度倍数，**默认 2** | 1080 宽显示 → 需要 2160 像素宽的图 |
| `--at 0,900,1800` | 按给定纵向偏移量分段滚动截取，逗号分隔 | 一页截三张，分别对应首屏、中段、底部 |
| `--full 3600` | 整页长图，参数是预估页面高度 | 长文档页、定价页 |
| `--device iphone` | 设备预设，可用 `iphone` / `android` / `desktop` | 手机 App 的 H5 页、移动端布局 |
| `--hide 选择器` | 截图前隐藏元素，可重复给 | `--hide ".cookie-banner" --hide "#promo-bar"` |
| `--login` | 弹一个真实窗口让用户登录一次，登录态存 `out/.browser-profile/` | 后台页面、需要账号的 SaaS |
| `--out out/shots` | 输出目录 | 与 `check_assets.py` 的扫描目录保持一致 |

常用组合：

```bash
# 后台仪表盘：先登录一次，然后截首屏与两个滚动位置
python scripts/capture.py https://app.acme.com/dashboard dashboard \
  --login --at 0,900,1800 --hide ".cookie-banner" --out out/shots

# 移动端页面：按 iPhone 视口出图，2 倍
python scripts/capture.py https://acme.com/m mobile-home --device iphone --factor 2 --out out/shots

# 定价页整页长图
python scripts/capture.py https://acme.com/pricing pricing --full 3600 --out out/shots
```

### 为什么必须 2 倍图

视频输出是 **1080×1920**。一张截图在画面里哪怕只占 60% 宽（约 648 px），源图也得有足够像素去支撑放大、缓动推近（Ken Burns）和平台二次压缩。按 2 倍算：**1080 宽显示 → 2160 像素**。1 倍图放进 1080 画面里推近 1.3 倍立刻发虚；2 倍图留出的余量正好覆盖推近与编码损耗。

**这条没有脚本能替你判**：脚本不知道这张图在画面里占多宽，`check_assets.py` 只能给下限护栏（宽度 <1000px 或 >3000px 各报一条 WARN）。所以「≥ 显示宽度 × 2」要你自己按画面占比核对：`media.py info out/shots` 看实际像素，对照计划里的显示宽度（1080 画布全屏 = 2160px，占 60% 宽 ≈ 648px 显示 → 源图 ≥1300px），再决定 `--factor`。

### 截图前的准备（不做这几步，截图基本要重来）

| 准备动作 | 怎么做 | 不做会怎样 |
| --- | --- | --- |
| 关掉 cookie / 订阅弹窗 | `--hide ".cookie-banner" --hide "#newsletter-modal"` | 弹窗盖住关键功能，整张作废 |
| 隐藏横幅与广告位 | `--hide ".promo-bar"` | 画面里出现"限时 5 折"，与片子的主张冲突 |
| 触发懒加载 | 用 `--at` 分段滚动，或 `--full` 整页 | 下半张图是灰白的占位骨架 |
| 切到有数据的演示账号 | 用 `--login` 登录演示账号，预先造 5~10 条真实感数据 | 空列表、`0 items`、`暂无数据` 出现在正片里 |
| 关掉鼠标悬停与焦点态 | 截图前把鼠标移开，或 `--hide` 掉 tooltip 类元素 | 留下一个孤零零的悬浮提示框 |
| 固定时间与时区 | 演示账号里的日期选一个近期确定日期 | 页面显示"3 天前"过期数据，改稿时又要重截 |

截图后立刻用 `media.py info out/shots` 看一眼实际像素宽，不合格当场重截，别拖到渲染前才发现。

## 3. `media.py`：素材整理

| 命令 | 用途 | 例子 |
| --- | --- | --- |
| `grab` | 抓取 Markdown 里引用的全部图片到本地目录 | `python scripts/media.py grab docs/readme.md -o out/shots` |
| `sheet` | 把目录里的图拼成联系表，用于快速审图 | `python scripts/media.py sheet out/stills --cols 4` |
| `crop` | 按目标比例预览实际裁切效果（不真裁，先看构图） | `python scripts/media.py crop out/previews shot-a.png shot-b.png --ratio 9:16` |
| `prepare` | 限宽并压到可放进工程的尺寸 | `python scripts/media.py prepare out/shots/full.png public/img/full.png --max 2800` |
| `info` | 列出目录里每张图的尺寸，检查是否够 2 倍 | `python scripts/media.py info out/shots` |

工作流固定成四步：`grab` 拉素材 → `info` 查尺寸 → `crop` 看竖屏裁切会不会切掉关键内容 → `prepare` 限宽放进 `public/img/`。

**`crop` 这一步不能省**：一张网页截图在竖屏里通常只能显示中间一条，先看裁切预览能提前发现"功能按钮被切掉了"。

## 4. 长截图放进竖屏的三种做法

长图（`--full` 出来的整页图）比例往往是 1:4 甚至更极端，直接等比缩进 9:16 会变成一条看不清的细线。三种正确做法：

| 做法 | 怎么做 | 适合 | 注意 |
| --- | --- | --- | --- |
| **纵向滚动** | 长图放在一个 `overflow: hidden` 的容器里，容器高度占画面约 55~65%，用 `translateY` 做缓慢上移 | 展示"页面很长、信息很全"的完整感 | 滚动全程 ≥1.2 秒；起止位置都要停在有内容的地方，别停在空白分栏上 |
| **分段截取** | 用 `--at 0,900,1800` 截成多张，每个功能点对应一张，逐张切换 | 三个功能点的 demo 段（最常用） | 每段配一句旁白；同一版式最多连用 2 次 |
| **等比缩放留白** | 整图按宽度铺满（约 80% 画面宽），上下留白放标题与说明 | 信息密度低的长图、定价页 | 缩放后正文小于 24 px 就不要用，改成前两种 |

判据一句话：**缩放后最小的正文小于 24 px（按 1080 宽算）就不能用第三种**，必须改成滚动或分段。

## 5. AI 生成图只能用在哪

| 允许 | 不允许 |
| --- | --- |
| 背景纹理、抽象色块、光斑 | 产品界面、产品截图 |
| 转场遮罩、划像图形 | 功能图标（会被当成真功能） |
| 章节封面的大字底图 | 数据图表、KPI 数字 |
| 情绪氛围图（不承载信息） | 真人头像冒充用户证言 |

判断标准只有一条：**这张图是否让观众以为它是产品的真实能力**？会，就禁止。
一旦用了 AI 图，必须在 `调研笔记.md` 里写明"AI 生成，仅作包装"，写清模型与 prompt 摘要。

## 6. 版权与授权记录

每张素材都在 `调研笔记.md` 里落一行，模板如下：

```markdown
# 调研笔记 · <产品名>

## 事实来源

| # | 事实 | 出处（URL / 文件） | 获取日期 | 备注 |
| --- | --- | --- | --- | --- |
| F1 | 注册用户 6 万 | 官网首页第 3 屏 | 2026-10-11 | 用户已确认可对外 |
| F2 | v3.2 新增自动分类 | CHANGELOG v3.2 | 2026-10-11 | 未发布功能，需加未确认标注 |

## 素材清单

| # | 文件 | 类型 | 来源 | 获取方式 | 授权条款 / 边界 | 署名要求 | 用在哪 |
| --- | --- | --- | --- | --- | --- | --- | --- |
| M1 | shots/dashboard@2x.png | 真实界面截图 | 自有产品 | capture.py --factor 2 | 产品方自有，可商用 | 无 | demo |
| M2 | shots/orders@2x.png | 真实界面截图 | 用户提供 | 微信发送原图 | 用户口头授权；真实客户名已打码 | 无 | demo |
| M3 | img/bg-01.png | AI 生成（包装） | 文生图 | prompt 摘要见下 | 生成工具条款允许商用 | 无 | hook 背景 |

## 音乐与音效

| # | 文件 | 曲名 / 来源 | 曲库条款 | 是否需署名 | 使用范围 |
| --- | --- | --- | --- | --- | --- |
| A1 | audio-src/music/track.mp3 | <曲名>，<曲库名> | 免费可商用，不得转售 | 建议署名（片尾字幕） | 全片 BGM |

## 字体

| # | 字体 | 来源 | 授权 | 用在哪 |
| --- | --- | --- | --- | --- |
| T1 | 系统黑体栈 | fonts.json 系统候选 | 随系统 | 全片 |
```

三条硬要求：

1. **用户提供的素材也要记录**，写明授权形式（口头/邮件/合同）与有没有打码。
2. **截图里出现第三方内容要单独标**：用户头像、客户 Logo、第三方品牌名，能打码就打码，不能打码要用户书面确认。
3. **改版时素材表跟着更新**，替换掉的素材保留行并标注"已弃用"，方便回溯。

## 7. 自检

- [ ] 全片真实素材 ≥6 张（>45 秒 ≥8 张），每个功能段落 ≥1 张
- [ ] 蒙太奇段由 ≥6 张真实作品组成
- [ ] 所有截图 `--factor 2`；`media.py info` 里的像素宽度 ≥ 该图在画面里显示宽度的 2 倍（1080 画布全屏 → 2160px）
- [ ] 截图前已隐藏弹窗/横幅，且用的是有数据的演示账号
- [ ] 长图用滚动 / 分段 / 缩放三选一，缩放后正文 ≥24 px
- [ ] AI 图只出现在包装位，且已在 `调研笔记.md` 标注
- [ ] `调研笔记.md` 的事实表、素材表、音乐表、字体表四张表齐全
