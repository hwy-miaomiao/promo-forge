# 配音与字幕

> **什么时候读这一篇**：**阶段 7 配音与字幕** 时读；写旁白稿（阶段 6 之前）就要先看第 3 节的写稿规则。

## 1. 免费 edge-tts 与中文音色

默认走免费路线：`voice.engine = "edge"`，用 edge-tts 生成配音，不需要任何 API key。只有想换更自然的音色时，才考虑 `--engine eleven`（需要 `ELEVENLABS_API_KEY`）。

### 常用 `zh-CN-*Neural` 音色

| 音色 | 性别 | 听感 | 适合什么产品 |
| --- | --- | --- | --- |
| `zh-CN-YunxiNeural` | 男 | 年轻、语速感偏快、有一点"讲述者"的味道 | **默认首选**：开发者工具、SaaS、效率类 App |
| `zh-CN-YunjianNeural` | 男 | 低沉、有力量、偏纪录片旁白 | 硬件、汽车、运动、发布会 |
| `zh-CN-YunyangNeural` | 男 | 标准播音腔、新闻感强 | 企业、金融、政务、严肃 B 端 |
| `zh-CN-YunxiaNeural` | 男 | 少年感、轻快 | 游戏、二次元、学生向产品 |
| `zh-CN-XiaoxiaoNeural` | 女 | 自然、亲和、最通用 | **默认首选**：生活方式、教育、电商、健康 |
| `zh-CN-XiaoyiNeural` | 女 | 温柔、慢一点、有耐心 | 母婴、心理、老年向、教程类 |
| `zh-CN-liaoning-XiaobeiNeural` | 女 | 辽宁方言味，接地气 | 本地生活、区域活动、幽默向 |
| `zh-CN-shaanxi-XiaoniNeural` | 女 | 陕西方言味 | 地方文旅、区域活动 |

挑选规则：

1. **音色跟着受众走**，不跟着品牌走。受众是财务/程序员 → 云希或云扬；受众是宝妈 → 晓伊。
2. 45 秒的片子**只用一个人声**，不要男女对播（信息量撑不住，还容易抢拍）。
3. 音色定下来写进 `timing.json` 的 `voice.voice`，**禁止在场景组件里另写音色名**。
4. `voice.rate` 默认 `+8%`；语速调整见第 4 节，**上限 +12%**。

## 2. `tts.py` 用法

```bash
python scripts/tts.py all                    # 按 timing.json 的 voice.lines 全部生成
python scripts/tts.py one <id>               # 只重生成某一句（改稿后用）
python scripts/tts.py audit                  # 审核：窗口内时长、尾部拖音、缺句
python scripts/tts.py voices [--lang zh]     # 列出可用音色（用来确认音色名拼写）
python scripts/tts.py preview --text "..."   # 用一句话试听当前音色
python scripts/tts.py stt <file>             # 可选：语音转文字反查读错字（需额外依赖）
```

标准流程：

```bash
# 1) 先确认音色名存在，别凭记忆写
python scripts/tts.py voices --lang zh

# 2) 给用户试听两个候选音色（AI 不能替用户拍板音色）
python scripts/tts.py preview --text "每天记账，是不是都要花十几分钟？"

# 3) 音色写进 timing.json: voice.voice / voice.rate
python scripts/tts.py all

# 4) 审核，任何 TOO_LONG / MISSING 都不许往下走
python scripts/tts.py audit
```

`tts.py audit` 的输出要按这张表读：

| 报告项 | 含义 | 处理 |
| --- | --- | --- |
| `OK` | 句子落在该场景窗口内 | 继续 |
| `TOO_LONG` | 生成的语音超过场景可用窗口 | **回去删字改稿**，见第 4 节 |
| `MISSING` | `timing.json` 里的这句话没有对应音频文件 | 跑 `tts.py all` 或 `tts.py one <id>` |
| `ECHO` | 尾部有明显拖音（长尾混响/呼气声）；脚本已自动截掉低于口径的低能量尾巴，重跑仍报说明尾巴本身能量不低 | **人工确认**：听一遍，决定换句尾用词还是换音色重生成 |
| 时长/窗口列 | 每句的实际时长与窗口 | 差值小于 0.15 秒的句子要提前预警（改稿会立刻超时） |

生成结果与统计写进 `audio-src/vo/`（含 `report.json`），音频文件按 `id` 命名，一句一个文件。
`report.json` 每句还记 `tail_trimmed_ms`（本轮自动截掉的拖音毫秒数，0 = 没截）；`engine` 是**本次实际**
用的引擎（`tts.py all --engine eleven` 时写 eleven，不是照抄 `timing.json`）。
缓存键包含文本/引擎/音色/语速；用 ElevenLabs 时还包含 `voice.settings` 与 `model`——改了这些参数就会重生成，
不会静默复用旧音频。edge-tts 的缓存键保持旧算法，升级脚本不会让已有项目全部重跑。

## 3. 写稿规则

旁白稿写进 `timing.json` 的 `voice.lines`，每句必须带 `id` / `scene` / `at` / `text` 四个字段：

```jsonc
"lines": [
  { "id": "01", "scene": "hook",  "at": 0.6,  "text": "每天记账，是不是都要花十几分钟？" },
  { "id": "02", "scene": "demo",  "at": 5.0,  "text": "现在只要拍一张小票，剩下的交给它。" }
]
```

六条写稿规则：

1. **口语化**。"实现自动化记账" → 改成"拍一张小票就行"。念出来别扭的句子，观众一定听不进去。
2. **一句话一个信息点**。一句里塞两个功能，观众只能记住前一个。45 秒的片子旁白**5~6 句**最舒服。
3. **语速按 5.5~6.5 字/秒写**（含标点停顿）。算式：`可用秒数 × 6 ≈ 字数上限`。例：hook 场景 4.5 秒，扣掉 0.6 秒入点与 0.5 秒留白，实际约 3.4 秒 → 上限约 20 字。
4. **避免多音字**。"行"（háng/xíng）、"重"（zhòng/chóng）、"还"（hái/huán）、"长"（cháng/zhǎng）——出现就用同义词替换。
5. **避免中英混读**。`API`、`SaaS`、`v3.2` 这类词念出来经常变成字母乱读。必须出现时：**写中文读法**（"接口"、"三点二版本"），英文缩写确认过发音才留。
6. **品牌名与网址必须"读得出来"**。中文名 + 英文域名混排最容易错，做法是把读音直接写进稿子：
   - 品牌"小账本" + 网址 `xiaozhangben.app` → 稿子写"小账本，现在就能免费下载"，网址**只上屏、不念**（或念"小账本点儿 app"并在 `需求确认.md` 记下读法）。
   - 缩写型品牌（`Acme`）→ 先问用户怎么读，别自己猜。

**每句 `at` 都必须是场景窗口内的时间点**，且与屏上大字的出现时间联动：屏上大字**最多比旁白早 1.5 秒**出现。

## 4. 超时了怎么办

`tts.py audit` 报 `TOO_LONG` 时，按这个固定顺序处理，**不许跳步**：

| 顺序 | 做法 | 说明 |
| --- | --- | --- |
| 1 | **删字改稿** | 删掉修饰语、重复信息、可推到下一句的内容。这是唯一正确的第一选择 |
| 2 | 拆句 | 一个长句拆成两句，分给同一场景内的两个 `at` 时间点 |
| 3 | 最多加速 **12%** | 改 `voice.rate`（如 `+8%` → `+12%`），或只对该句加速；超过 12% 会明显听出机器味 |
| ❌ | 硬压时长（截断音频、拉时间轴） | **禁止**。会把句子切掉尾字或让语速忽快忽慢 |

公式化判断：句子所需时长 ≈ `字数 / 6.5`（秒，按快语速算）。若这个值已经大于场景可用时长，**只能删字**，加速救不回来。
改稿后重跑 `python scripts/tts.py one <id>` 与 `python scripts/tts.py audit`，两处都过才算好。

## 5. 尾部拖音（ECHO）与切静音

- `ECHO` 的成因：模型在句尾拖长音、或留下了吸气/房间混响。听感上像"最后一个字粘在后面"。
- **判定标准**：句尾低于**人声语音帧平均电平 -40 dB** 的部分若持续超过 **0.25 秒**，就是拖音。
  `tts.py` 在切静音时就会按这个口径**真正截掉**：先用 `silenceremove` 切掉 -45dB 以下的头尾静音，
  再量尾部低能量，超过 0.25 秒就用 `atrim` 截断并留 15ms 淡出（避免"啪"的爆音），
  截掉多少写进 `report.json` 的 `tail_trimmed_ms`。切掉后句长可能变短，需要重新核对该句是否还和字幕停留时间匹配。
- 处理顺序：① 先让脚本自动切静音并截拖音 → ② 重跑 `audit`：仍报 `ECHO` 说明尾巴能量并不低（不是纯拖音），
  改稿处理 → ③ **换句尾用词**（避免以"了""的""吗"这类虚词收尾）→ ④ 再换音色重生成（最后手段）。
- 反向注意：**不要切太狠**。句尾切到 0.15 秒以内会听起来"被掐断"，尤其疑问句。切静音后要人耳过一遍。

## 6. 字幕排版规则

字段全在 `timing.json` 的 `captions` 里，组件按它排版，**不许硬编码**：

```jsonc
"captions": { "enabled": true, "maxChars": 13, "maxLines": 2, "bottom": 0.18 }
```

| 规则 | 数值 | 说明 |
| --- | --- | --- |
| 单行字数 | **≤13 字** | 含标点；超过就断行，不许缩字号硬塞 |
| 行数 | **最多 2 行（硬闸门）** | 第 3 行不是警告：`subtitles.py srt/ass/burn` 直接 `ERROR` 并以退出码 1 收场，回去删字或调大 `maxChars` |
| 字号 | **脚本自动换算，不许手写死** | `min(画布高 × 0.038, (画布宽 − 左右留白) / maxChars)`：竖屏 1080×1920 时 = min(73, 864/13) = **66px**；只按高度算的 73px 让 13 个全角字（949px）越过右侧 14% 留白，压到 66px 后是 858px，正好落在 864px 安全区里 |
| 底部安全区 | **距底部 18%**（`bottom: 0.18`） | 竖屏安全区下边界就是 18%，字幕取同一个数：画面里的 `<Caption>` 与烧入的硬字幕（`subtitles.py`）落在同一像素 |
| 屏上大字 vs 旁白 | 大字**最多比旁白早 1.5 秒** | 早了观众会先读到、后听到，产生错位感 |
| 停留时长 | **≥ 字数 / 6 + 0.35 秒**（活到人声读完） | 13 字 → ≥2.52 秒；这句没读完就切走，等于没写 |
| 右侧留白 | 右边 **14%** 不放字幕 | 平台互动按钮会压在上面 |
| 断行位置 | 在标点或语义边界断，**不许拆词** | `URL`/英文单词/数字整段不可拆，装不下就整词下移；单个词本身比整行还宽才从中间硬切并 WARN。所以「网址太长放不进 2 行」时脚本会报 ERROR：缩短网址，或调大 `captions.maxChars`（字号会自动跟着缩） |

**ASS 的 `Fontsize` 是行高、不是 em**：libass 按字体的 `(hhea.ascent − hhea.descent)/unitsPerEm` 归一 ——
同一个 `Fontsize`，微软雅黑实际只有约 **0.758 em**（该比值 ≈1.32），SimHei / SimSun ≈1.0 em。
所以上表的 66px 是 **em 像素**，`subtitles.py ass` / `burn` 写 ASS 时会自动乘回字体比例
（微软雅黑：em 66px → `Fontsize≈87.1`），烧进画面的字才和画面 `<Caption>` 同尺寸；
`ass --fontsize` 覆盖的也是 em 像素口径。别手写 `Fontsize=66` 直接塞进 ASS（不换算时微软雅黑上小约 24% 且不报错）。

自检口诀：**13 字、2 行、18%、1.5 秒、字数/6+0.35**。五项里任何一项不过，先改文案再改排版。

## 7. 可选：用 STT 反查读错字

合成音色最容易错的是多音字和英文缩写，而 AI 听不出自己念错了。用 `stt` 做闭环：

```bash
python scripts/tts.py stt audio-src/vo/02.mp3
```

把转写结果和 `timing.json` 里的原文逐字对照：

- 不一致的字 → 就是读错的字，改稿换同义词，或用拼音化改写（把"重"改成"重新/重量"里确定读音的那个词）。
- 数字与英文缩写重点核对：`v3.2` 可能被读成"v 三点二"或"v 三二"，以转写结果为准。
- 这一步依赖可选的语音识别依赖，装不上就**人工听一遍**，不能跳过核对。没装 `faster-whisper` 时
  `python scripts/tts.py stt <file>` 会打一行 `ERROR:` 并**以退出码 1 收场**（不再静默跳过）——
  这是有意的：`stt` 是校验命令，「没跑成」不能算「校验通过」。真不想跑这一步就压根别调 `stt`，
  改成人工听一遍并在 `需求确认.md` 记一句。
