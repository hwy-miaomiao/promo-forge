# 踩坑记录

> **什么时候读这一篇**：**开工前通读一遍**，避免重复踩坑；排查问题时按分类检索，用【现象】里的原话当搜索关键词。

格式统一为【现象】【原因】【解决】，能直接照着排查。

## 一、内容 / 文案坑

**1. 旁白念不完**
- 【现象】`tts.py audit` 报 `TOO_LONG`；成片里某句话被切掉半个字。
- 【原因】写稿时按"读起来差不多"估的，实际字数超了场景窗口。
- 【解决】按 **5.5~6.5 字/秒** 重算：`字数上限 ≈ 可用秒数 × 6`。**先删字**，删不动再拆句；最多加速 **12%**（`voice.rate` 从 `+8%` 调到 `+12%`），禁止截断音频硬压。

**2. 停顿时长拍脑袋定**
- 【现象】字幕早早淡出、旁白还在念；或者旁白念完了画面还在干等。
- 【原因】字幕停留没按公式算。
- 【解决】停留时长 **≥ 字数/6 + 0.35 秒**（配音 5.5~6.5 字/秒，字幕要活到人声读完；按 字数/8+0.4 算 13 字只停 2.03 秒，人声还没念完字幕就没了）；屏上大字**最多比旁白早 1.5 秒**出现。两项都写进 `timing.json`，不要写在组件里。

**3. 品牌名 / 网址写错**
- 【现象】审图时发现域名少了个字母，或英文名大小写与官网不一致；成片已渲染完。
- 【原因】手打品牌名；中英混排时容易漏字符。
- 【解决】从官网**逐字符复制**写进 `timing.json` 的 `brand.name` / `brand.url`，渲染前在联系表上逐张核对拼写（校验清单 B4）。

**4. 文案是"赋能、闭环、一站式"**
- 【现象】用户反馈"看不懂你们在说什么"。
- 【原因】写的是行业黑话，不是观众的话。
- 【解决】把每个抽象词换成动作："赋能记账" → "拍一张小票"。写完念一遍，念着别扭就重写。

**5. CTA 一闪而过**
- 【现象】网址只出现 1 秒，观众根本来不及记。
- 【原因】把 CTA 当普通镜头排了。
- 【解决】网址/CTA 停留 **≥2.5 秒**，且放在**全片能量最高处**（用 `music.py bars` 的能量表定位）。CTA 与未发布标注同屏时留 ≥40 px 间距。

**6. 事实没记来源**
- 【现象】改版时想说清"6 万用户"是谁说的，翻遍聊天记录找不到。
- 【原因】阶段 1 的调研结论只写进了脑子。
- 【解决】每个事实都在 `调研笔记.md` 记一行：事实、出处、获取日期、备注。用户没确认过的数据不写进成片。

**7. 未发布的界面直接上了正片**
- 【现象】内测页面出现在片子里，发布后被认为"官方已确认"。
- 【原因】漏了未发布标注。
- 【解决】全片常驻 `抢先看 / 未经官方确认` 小字，落在竖屏安全区内、不被字幕遮挡，并在 `需求确认.md` 写明依据日期。截图里的真实数字打码，合作方 Logo 先问授权。

## 二、视觉坑

**8. 截图被 CSS 压扁**
- 【现象】网页界面在画面里被横向拉宽或纵向压扁，圆形按钮变成椭圆。
- 【原因】图片被同时指定了宽和高，且没有锁定比例；`object-fit` 没设成 `contain`，或父容器用了 `max-width` 之后又给了固定高度。
- 【解决】只给一个方向的尺寸，另一个方向 `height: auto`（或 `width: auto`）；容器加 `object-fit: contain` + `object-position`；改完抽帧复核圆角按钮是否还是正圆。

**9. 长截图缩放后字看不清**
- 【现象】整页长图等比缩进竖屏后，正文糊成一团灰线。
- 【原因】长图比例太极端（1:4 以上），缩到 1080 宽后正文不足 24 px。
- 【解决】改成三种做法之一：**纵向滚动**（容器占画面 55~65%，`translateY` 缓慢上移，≥1.2 秒）、**分段截取**（`capture.py --at 0,900,1800` 分三张）、**等比缩放留白**（仅当缩放后正文 ≥24 px 才可用）。

**10. 字体缺字变方块**
- 【现象】画面里出现 ▯▯ 或空白；`check_assets.py` 报字体缺字。
- 【原因】像素字体、手写字体没有中文字库；或用了不在 `template/fonts.json` 覆盖范围内的特殊符号。
- 【解决】中文一律 fallback 到黑体栈；标题特殊字体只用于**能确认覆盖的字符**；用 `check_assets.py` 在渲染前拦下来，不要等到成片。

**11. emoji 在部分系统不渲染**
- 【现象】本地预览正常，别人电脑/服务器上 emoji 变成空白或黑白轮廓。
- 【原因】emoji 依赖系统字体（Apple Color Emoji / Segoe UI Emoji / Noto Color Emoji），渲染机器上不一定有。
- 【解决】正片里不用 emoji，换成 SVG 图标或文字；品牌相关的表情符号做成图片资源放进 `public/img/`。

**12. 用 1 倍图当素材**
- 【现象】推近镜头一放大就发虚，`check_assets.py` 报图片宽度不足。
- 【原因】用了 AI 工具自带浏览器的截图（通常 1 倍分辨率）。
- 【解决】用 `python scripts/capture.py <url> <name> --factor 2`：**1080 宽显示需要 2160 像素**。复核命令：`python scripts/media.py info out/shots`。

**13. 截图里是空数据**
- 【现象】正片里的界面显示"暂无数据"、"0 items"、全是骨架占位。
- 【原因】用新注册账号截图，或懒加载没触发。
- 【解决】用 `--login` 登录**演示账号**并预置 5~10 条真实感数据；懒加载用 `--at` 分段滚动或 `--full` 触发后再截。

**14. cookie 弹窗 / 促销横幅留在画面里**
- 【现象】每张截图都盖着一个"接受 Cookie"弹窗或"限时 5 折"横幅。
- 【原因】截图前没清理页面。
- 【解决】`--hide ".cookie-banner" --hide ".promo-bar"`（可重复给）；截图后先跑 `media.py sheet` 扫一眼再进工程。

**15. 横竖屏切换后破版**
- 【现象】9:16 里好好的版式，改成 16:9 后文字出界、元素重叠。
- 【原因】尺寸写死了像素值。
- 【解决】所有布局用**相对单位**：百分比或 `useVideoConfig()` 的宽高比推导；安全区按比例算（竖屏 上 10% / 下 18% / 左 6% / 右 14%），横屏重新推导且必须再抽帧审图。

**16. 文案溢出安全区 / 被平台 UI 遮挡**
- 【现象】字幕右下角被平台的点赞、评论按钮压住；或者文字顶到屏幕最上沿。
- 【原因】按"整屏居中"排版，没留安全区。
- 【解决】右侧 **14%** 永远不放内容；字幕距底 **18%**（= 下安全区边界，`captions.bottom` 取同一个数，这样画面字幕与烧入硬字幕同位置）；屏上大字落在上 10% 之下。审图时用校验清单 B1 逐张打勾。

**17. 颜色在不同帧里不一致**
- 【现象】同一个强调色，hook 段偏亮、cta 段偏暗。
- 【原因】组件里各自写了 hex，或叠了不同透明度的背景。
- 【解决】颜色只从 `timing.json` 的 `brand.colors`（`bg`/`fg`/`accent`）取，禁止组件内硬编码；叠色统一走同一个工具类。

## 三、音频坑

**18. ffmpeg 没装，混音直接失败**
- 【现象】`mix.py` 报错退出，`public/audio/music.wav`（`timing.json` 的 `music.file`）根本没生成，`check_assets.py` 随后报混音不存在。
- 【原因】ffmpeg/ffprobe 是硬依赖，但系统里没有或不在 PATH 上。
- 【解决】`python scripts/doctor.py` 会报 `MISSING`，按它给的方式安装 ffmpeg 并确认 `ffmpeg -version` 有输出。**没有 ffmpeg 不要往下走任何一步。**

**19. 试听时响度不一致，用户挑错了曲子**
- 【现象】用户选了"听起来最响"的那首，实际是音量被拉高了，不是曲子更好。
- 【原因】候选曲目原始响度不同，直接给人听。
- 【解决】先用 ffmpeg `loudnorm` 把候选统一到 **-14 LUFS / 真峰值 -1 dBFS**，再叠上同一句人声给人听（命令见 `references/配乐与卡点.md` 第 6 节）。

**20. 音乐盖住人声**
- 【现象】旁白某些字听不清，尤其是"是/四""知/吃"这类音。
- 【原因】音乐没做 ducking，或音效叠在同一个时间点。
- 【解决】硬性要求：每句人声比该处音乐高 **≥6 dB**（脚本里的 `vo_margin`）。用 `python scripts/mix.py --env` 打印响度包络，定位到具体是哪一句被盖，把该句 `at` 与场景窗口对齐后重跑 `mix.py`。

**21. 母带没做，平台二次压缩后忽大忽小**
- 【现象】同一支片子发到不同平台，一个偏小一个爆音。
- 【原因】没有统一母带响度。
- 【解决】母带 **-14 LUFS / 真峰值 -1 dBFS**；片头 **0.3 秒**淡入、片尾 **0.6 秒**淡出。`check_video.py` 要求实测落在 **-16~-12 LUFS**。

**22. 成片被判定有空档**
- 【现象】`check_video.py` 报 **≥1.0 秒**的静音段。
- 【原因】音乐剪接处断了（`music.segments` 拼接点没对齐）；两句旁白之间留白过长；某场景窗口比内容长。
- 【解决】核 `music.segments` 的剪接点是否落在小节线上；在空档处补铺底音；核 `scenes` 是否首尾相接、不留缝。

**23. 节拍对不上，卡点全部错位**
- 【现象】镜头切换"差一点点"才踩上拍子；`music.py` 报的 drop 位置听着不对。
- 【原因】把**音乐时间**当成**视频时间**填进 `drop`；或 `offset` 忘了按 `musicOffset = drop - downbeat` 计算（爆发时刻 − 重拍时刻，别写成 `downbeat - drop`）。
- 【解决】`drop` 一律写视频时间；重拍比 drop 晚就得到负 offset（跳过前奏），重拍比 drop 早就是正 offset（`offset = 4.0 - 2.0 = +2.0`，音乐从视频第 2 秒起播，**视频前 2 秒必须补低能量铺底**，否则开场是干声）。
- 【补充】节拍一致性 **≥0.9** 才算过；低于 0.9 换曲子，不要硬修。

**24. 曲子有段突然静音**
- 【现象】成片某 1.5 秒完全没有音乐，被闸门判成空档。
- 【原因】挑曲子时只听了前 15 秒，副歌前的 break 是空的。
- 【解决】挑曲时用 `music.py bars` 看逐小节能量，**避免选有突然静音的曲子**；已选中的用 `music.py cut` 跳过该段。

**25. 用了流行歌被平台下架**
- 【现象】视频发布后被静音或下架，提示版权。
- 【原因】用了流行歌/影视 BGM，哪怕只有 3 秒。
- 【解决】只用**免费可商用曲库**；把曲名、曲库名、条款链接、下载日期记进 `调研笔记.md` 的"音乐与音效"表；注意多数曲库要求署名、禁止转售曲子本身。

## 四、工程坑

**26. Windows 上 `python` 与 `python3` 不是一回事**
- 【现象】文档里的 `python3 scripts/tts.py all` 在本机报"不是内部或外部命令"。
- 【原因】Windows 通常只有 `python`（或 `py`），没有 `python3`；macOS/Linux 反之。
- 【解决】本仓库文档统一用 `python`；Windows 上若 `python` 也找不到，用 `py -3` 或把 Python 加进 PATH。用 `python --version` 确认 ≥3.9。

**27. 路径含中文导致打包/渲染失败**
- 【现象】Remotion 打包阶段报找不到模块，但路径明明是对的。
- 【原因】工程目录或用户目录含中文、空格、`&` 等字符，某些工具链在传参时被截断或转义。
- 【解决】工程放在纯 ASCII 路径下（如 `D:\work\promo\acme-app`）；`outputs/` 与 `宣传片/` 这类中文目录只在路径允许时使用，出问题第一时间把整个工程移到英文路径重试。

**28. 渲染日志报 `cannot be decoded` 但进程退出码 0**
- 【现象】命令"成功结束"、文件也生成了，但片子缺画面或缺声音。
- 【原因】个别素材解码失败被跳过，进程并未失败退出。
- 【解决】**一律按失败处理**。用 `python scripts/check_video.py out/final-1080p.mp4 --log out/render.log` 扫日志；出现 `cannot be decoded` / `Error:` / `failed to load` 就按日志里的文件名逐个修（常见是字体没打包、图片路径写错、音频编码不支持）。

**29. 大图内存爆掉**
- 【现象】渲染中途进程被系统杀掉，或报内存分配失败。
- 【原因】把几千像素的 2 倍长图原样塞进 `public/img/`，并发渲染时每帧都要解码。
- 【解决】用 `python scripts/media.py prepare <src> <dst> --max 2800` 限宽（先看 `media.py crop <out> <file...> --ratio 9:16` 确认裁切构图）；渲染时降并发（`package.json` 里 `render:*` 脚本自带 `--concurrency=12`，机器内存小就改那个数，注意这是 Remotion 渲染器的参数、不是 `media.py` 的）；不需要的超大原图不要放进工程。

**30. 改了代码没生效（缓存）**
- 【现象】改完场景组件，抽帧还是旧画面。
- 【原因】Remotion/Node 的缓存、旧的 `out/stills` 没清、或者改的是 `template/` 本体而不是项目副本。
- 【解决】先确认改的是**输出目录里的副本**（`template/` 本体永远不改）；重跑抽帧时带上 `--keep` 之外的清理，或删除 `out/stills` 再跑；必要时清 `node_modules/.cache`。抽帧命令：`npm run stills -- --scenes`。

**31. `node_modules/` 与 `out/` 被提交进版本库**
- 【现象】一次提交几百 MB，仓库克隆不动。
- 【原因】忘了 `.gitignore`，或工程放在了未忽略的目录里。
- 【解决】项目根目录的 `.gitignore` 要覆盖 `node_modules/`、`out/`、`public/audio/*`、`public/img/*`、`audio-src/music/*`、`audio-src/vo/*`（保留 `.gitkeep`）；Skill 用法下提醒用户把 `<工作区>/宣传片/` 加进 `.gitignore`。

**32. 改动 `timing.json` 后画面/音频对不上**
- 【现象】改了 `duration` 或 `scenes`，成片时长还是旧的，字幕与旁白错位。
- 【原因】`timing.json` 是**整支片子唯一事实来源**，改了它就必须重跑受影响的每一步。
- 【解决】对照影响范围重做：只改字幕文案 → 场景组件 → 重渲；换配音音色 → `tts.py` → `mix.py` → 只替换成片音轨；改配乐 → `music.py` 重新分析 → 更新 `beat/bar/drop` → 场景卡点微调 → 重渲；换风格 → 回阶段 2 重出样帧 → 场景大改 → 全流程重跑。**`duration` 必须等于最后一个场景的 `end`。**

**33. 端口被占用就想着换端口**
- 【现象】`npm run web:serve` 报端口占用。
- 【原因】上一次的服务没关，或别的程序占着 18765。
- 【解决】先结束旧进程再重试；确实需要换端口时改命令行的 `-p` 参数，并在交付话术里写清**实际访问地址**，不要把冲突地址发给用户。

**34. 复制模板后没装依赖 / 装错了目录**
- 【现象】`npm run dev` 报 `Cannot find module 'remotion'`、`vite: not found`，或者抽帧脚本直接起不来。
- 【原因】只做了 `cp -r template <输出目录>` 就往下走。模板里**不含 `node_modules/`**，依赖必须在**副本目录里**装一次；也有人在本体 `template/` 里装，副本照样缺依赖。
- 【解决】按阶段 3 的顺序走完整三步：`cp -r template <输出目录>` → `cd <输出目录>` → `pnpm install`（**没装 pnpm 就 `npm install`**，首次会下载 Remotion 依赖）→ `python scripts/doctor.py` 在副本内再体检一次。`template/` 本体永远不装依赖、不改动。

**35. 新写的场景没加进注册表，渲染出来还是示例画面**
- 【现象】`src/scenes/` 里明明新建了组件，抽帧却出不来，成片里还是 `Hook / Demo / Proof / Cta` 这几段示例。
- 【原因】场景要经 `src/scenes/index.ts` 的注册表被 `Promo` 收集，只放一个 `.tsx` 文件不会被渲染；或者组件在场景窗口外没有 `return null`，几段画面叠在一起。
- 【解决】`src/scenes/` 里的 `Hook / Demo / Proof / Cta` 是**可直接运行的示例场景**（零外部素材也能出画面），照着写自己的场景；不需要的示例文件删掉后**必须同步改 `src/scenes/index.ts` 的注册表**。每个组件按 `timing.json` 的 `scenes` 窗口判断显示，窗口外一律 `return null`。改完跑 `npm run stills -- --scenes` 确认每段都出图。

**36. 成片比混音输出轻了整整 4 dB**
- 【现象】`mix.py` 报成品 -15.4 LUFS，抽帧和画面都正常，但 `check_video.py` 判 `ERROR: 响度 — Integrated -19.9 LUFS 不在 [-16, -12] 区间内`；或用户反馈"成片比试听时小很多"。
- 【原因】`public/<music.file>` 是 `mix.py` **已经混好、已经母带过**的成品轨（音乐床电平在混音阶段就用掉了 `music.gain`），而 `src/Promo.tsx` 的 `<Audio>` 又写了一次 `volume={TIMING.music.gain}` —— 播放端把 0.6 再乘一遍，整片就掉 4.4 dB（实测 -15.4 → -19.9 LUFS）。
- 【解决】`<Audio src={staticFile(TIMING.music.file)} />` **不要带 `volume`**：`music.gain` 只在 `mix.py` 里生效（`timing.json` 的字段注释里已注明）。改完必须用真正的 1080p 成片跑一次 `check_video.py` —— 短片段预览很容易漏掉这个坑。

**37. 字幕烧进画面后跑到顶上去了（ffmpeg 退出码还是 0）**

- 【现象】`subtitles.py burn` 成功、片子也有字幕，但字幕贴在**画面顶部**；ffmpeg 退出码 0、日志里一条警告都没有。
- 【原因】ASS 里 `Alignment=2`（底部居中）的 `MarginV` 语义是「文字底边离**画面底边**的距离」，
  写成 `(1 - captions.bottom) × 画布高` 就成了「离底 1613px」= 离顶 307px。
- 【解决】`MarginV = captions.bottom × 画布高`，再夹进下 18% 安全区（`subtitles.py` 的 `SAFE_BOTTOM`，夹到时打 WARN）。
  `captions.bottom` 要取 **0.18**：0.18 × 1920 = 346 = 安全区线，画面里的 `<Caption>` 与烧进去的 ASS 因此落在同一像素；
  取 0.16（旧模板默认值）会算出 307 < 346，**每次烧字幕都被夹取并打一条 WARN**，成片里画面字幕比硬字幕低 39px。
  这类「渲染器不报错、位置全错」的问题只能靠**抽帧目视**发现：`--preview 8` 之后打开 `out/verify-subs/*.png` 看一眼。

**38. 硬字幕和画面自带的字幕叠成两行糊字**

- 【现象】烧完硬字幕，底部出现两行互相重叠的字，哪一行都读不清。
- 【原因】画面里的 `<Caption>` 组件和烧进去的 ASS 都由 `captions.bottom` 定位，位置必然重合。
- 【解决】先渲染一版**不带画面字幕**的成片再烧：`npm run render:1080:nosubs`（内部传 `--props=props-nosubs.json`，
  把 `withCaptions` 设成 false）→ `python scripts/subtitles.py burn out/final-1080p-nosubs.mp4 -o out/final-1080p-hard.mp4`。
  `burn` 在 `captions.enabled=true` 时也会打 WARN 提醒这件事。

**39. Windows 下 ffmpeg 的 `ass=` 滤镜路径怎么写都不对**

- 【现象】`Unable to parse option value ... as image size`、`No such file or directory`，路径里的空格和中文还会被吃掉。
- 【原因】滤镜参数里 `\` 是转义符、`:` 是 key:value 分隔符，`F:\工程\out\zh.ass` 会被拆烂。
- 【解决】三条一起做：反斜杠换成正斜杠、盘符的 `:` 写成 `\:`、**整条路径用单引号包住**（只做前两条仍然失败）。
  路径里含单引号时无解，只能把工程放到不含单引号的目录。脚本内部已经按这套规则生成滤镜脚本文件
  （`-/filter_complex <文件>`，`-filter_complex_script` 在 ffmpeg 7.1 已废弃），不要手写这条命令。

**40. libass 会静默换字体，一行中文全变方块而退出码是 0**

- 【现象】字体的第一步声明的 `PingFang SC`（macOS 专属）在 Windows 上被 fontconfig 解析成**不含汉字**的
  Cascadia Code，整行字幕变方框，ffmpeg 退出码仍然是 0。
- 【原因】fontconfig 只认「字体名能不能解析」，不保证解析出来的字体有你要的字形。
- 【解决】字幕字体要**按候选清单逐个验证**：`fc-list` 建索引 + 族名匹配 + 用 fontTools 读 cmap 确认有字形，
  最终落到 `Microsoft YaHei` 这类真的有汉字的字体。

**41. Pillow 的 `getmask(ch).getbbox()` 判不出缺字**

- 【现象】用子集字体画标题或联系表标签，缺的字被画成方块或空白，但检查却报「字形存在」。
- 【原因】Pillow 会自己做字体回退：字体 cmap 里没有这个字，它照样借一个字形返回，`getbbox()` 非空。
- 【解决】判缺字要读字体自己的 cmap：`fontTools.ttLib.TTFont(path)` 之后 `ord(ch) in font.getBestCmap()`；
  选字体时顺着候选清单换到「排得全」的那个，别信 `getbbox()`。
  另外：`fonts.json` 的 `check.systemCandidates` 首位放的是**子集字体**（只有 342 个字），
  拿它给工具画中文标签一定会缺字 —— 工具链自己的标签要用系统字体。

**42. 交付预检说「码率偏低」，其实是 CRF 压出来的**

- 【现象】`deliver.py check --platform all` 通常只报 **一条** WARN：**视频号**「码率 1.26 Mbps < 建议 ≥10 Mbps」。
  这条现在标「官方建议值（非硬限制）」——官方原文用词是「建议」，不是拒收门槛。
  抖音 / 小红书 / YouTube Shorts 的码率、以及 Shorts 的体积上限没有官方数字，标「需人工确认」，
  只打 INFO、不参与判定（V11 修好后不再「每平台各刷一条 WARN」）。
- 【原因】Remotion 用的 `--crf 14` 是恒定质量编码，深色、静止画面多的片子码率天然低（画质并不差）；
  平台的「建议码率」是按复杂素材给的。
- 【解决】这是 WARN 不是 ERROR：画面复杂、或者平台二压明显时，把 `--crf` 调到 10~12（或改 `--video-bitrate`）重渲；
  确认画质没问题就可以照原样投。投之前一定自己看一遍成片，别只看闸门的绿字。

**43. ASS 字幕里的 `{}`、`\N`、`\n`、`\h` 是语义字符**

- 【现象】把含花括号或反斜杠的文案直接拼进 ASS，导出成功但字幕内容错位、换行乱掉，甚至整行消失。
- 【原因】ASS 把这些字符当控制码：`{...}` 是样式覆盖块、`\N` / `\n` 是硬 / 软换行、`\h` 是不换行空格，直接拼会改掉文本结构。
- 【解决】拼字幕一律走 `subtitles._escape_ass_text()`（`\{` / `\}` + 反斜杠后插 U+200B 零宽空格）。
  别图省事把 `\` 换成 `\\` —— 实测无效，第二个反斜杠和后面的字母会重新组成转义。

**44. PowerShell 的 `>` 重定向写出来的是 UTF-16 日志**

- 【现象】`npm run render:1080 > out/render.log 2>&1` 之后，`check_video.py` 报日志读不了 / 乱码，或者看起来一个错误都没匹配到。
- 【原因】Windows PowerShell 5.1 的 `>` / `Out-File` 默认编码是 UTF-16LE；渲染日志按 UTF-8 读会得到 NUL 和乱码。
- 【解决】日志用 `... | Out-File -Encoding utf8 out/render.log`（PowerShell 7+ 的 `>` 默认 UTF-8）。
  `check_video.py` 现在能按字节识别 UTF-16 BOM / 无 BOM 的 UTF-16 并打 WARN 留痕，但仍推荐 UTF-8 日志。

**45. 片尾被静音检测骗过：音轨比视频短**

- 【现象】`check_video.py` 的空档检测通过，但成片最后几秒没声音（或播放器提前结束音频）。
- 【原因】空档检测用 ffmpeg `silencedetect`，它只在音频流内部找静音；音频流本身比视频短时，缺的那段根本不在音频流里，检测不到。
- 【解决】`check_video.py` 现在单独比时长：有音轨但比视频短 >0.3 秒 = ERROR（`AUDIO_SHORTER_TOLERANCE_S`）。
  渲染 / 混音时别用 `-shortest` 把音轨截短；`mix.py` 之后重新核一遍音轨时长。

**46. 网页版打开一片白屏，console 报 `Cannot read properties of undefined (reading 'length')`**

- 【现象】`npm run web:build && npm run web:serve` 后页面空白，控制台报 `getStaticFiles()` 返回 undefined 后 `.length` 出错。
- 【原因】静态文件清单没注入（如直接用 `file://` 打开、或构建配置变化）时 `getStaticFiles()` 返回 undefined，
  `files.length` 直接抛错，React 整棵树挂掉，看起来就是白屏。
- 【解决】模板已加两层兜底：`web/main.tsx` 的 `<BootErrorBoundary>` 显示「网页版加载失败」+ 修复提示；
  `src/Promo.tsx` 对 `getStaticFiles()` 做 `Array.isArray` 守卫（`MUSIC_FILE_EXISTS` 同处）。遇到白屏先重新 `npm run web:build`，再看浏览器 console。

**47. 日志编码混杂时，报错词一个都匹配不到（闸门静默放行）**

- 【现象】渲染日志看起来有内容，`check_video.py` 也没报「日志缺失」，但日志里明明写过 `Error:` / `failed to load`，闸门却全 OK。
- 【原因】日志不是纯 UTF-8：PowerShell 5.1 的 `>` 默认写 UTF-16LE（见 #44），多段命令追加重定向时还会拼成 UTF-16 + UTF-8 的混合体；按 UTF-8 解码得到 NUL / 乱码，ASCII 报错词自然匹配不到。
- 【解决】`check_video.py` 现在按字节识别 UTF-8 / UTF-16 BOM 与无 BOM 的 UTF-16，编码可疑时先 WARN 留痕，再按 latin-1 兜底扫一遍 ASCII 报错词（任何字节都能映射成字符、不会抛异常）；仍推荐 `... | Out-File -Encoding utf8 out/render.log` 写日志。

**48. `timing.json` 里写 `NaN` / `Infinity`，或图片「头好数据断」**

- 【现象】JSON 里填了 `NaN` / `Infinity`（Python 的 `json.load` 默认能读、编辑器也不报错），时长 / 节拍 / 窗口算出离谱值却 0 ERROR 通过；或者一张 PNG 宽高读得出来，渲染 / 烘焙到一半才炸。
- 【原因】`NaN` 与任何数比较都是 False，会绕过所有范围判断；图片检查过去只读 IHDR 头，不校验 IDAT 是否完整。
- 【解决】`check_assets.py` 现在把 `duration` / `scenes[].start,end` / `music.beat,bar,drop,gain` / `voice.lines[].at` / `voice.rmsDb,duckDb` 里的非有限数字判 ERROR（`mix.py` 同口径）；图片会真解码（`image.load()`），截断 PNG 判 ERROR。手改 `timing.json` 或用脚本重写时别留下 `NaN`。

**49. ASS 的 `Fontsize` 是行高、不是 em：微软雅黑上硬字幕会小一圈**

- 【现象】按画面公式算出 66px、写 `Fontsize=66` 烧硬字幕，微软雅黑上字明显比画面里同公式的 `<Caption>` 小（实测约 24%），ffmpeg 退出码 0、没有任何报错。
- 【原因】ASS / libass 的 `Fontsize` 归一基准是字体的 `(hhea.ascent − hhea.descent)/unitsPerEm`，不是 em。微软雅黑该比值 ≈1.32（实际只有 `Fontsize × 0.758`），SimHei / SimSun ≈1.0。
- 【解决】`subtitles.py ass` / `burn` 会按 `fontTools` 读到的字体度量自动补偿（em 66px → `Fontsize≈87.1`，日志打「ASS 字号补偿」）；`--fontsize` 传的是 em 像素口径。别手抄 `Fontsize=66`。

**50. `subtitles.py burn` 需要 ffmpeg 6+：旧构建报 `Unrecognized option '/filter_complex'`**

- 【现象】用 2018 年的 ffmpeg 构建烧硬字幕，命令直接失败：`Unrecognized option '/filter_complex'. Error splitting the argument list: Option not found`。
- 【原因】`burn` 生成滤镜图后用 `-/filter_complex <文件>` 交给 ffmpeg（避免 `-vf "ass=路径"` 的三层转义），这种「`-/选项` 从文件读值」的写法旧构建不认；libass 也要新构建才带。
- 【解决】装 ffmpeg 6+ 的完整构建（含 libass）再烧，7.1 实测正常；Remotion compositor 的精简构建只能渲染，不能烧字幕。

**51. ffprobe 装坏时会被误报成「文件损坏」**

- 【现象】`deliver.py check` / `check_video.py` 对着好成片报「读不了 / 不是有效 MP4 / 探测失败」，绕一圈才发现是 ffprobe 本身跑不起来（缺 DLL、装了一半）。
- 【原因】脚本拿到 ffprobe 非 0 退出码时按「文件坏了」报错，环境问题与文件问题共用一套文案（已知的体验问题，脚本暂未区分）。
- 【解决】先 `ffprobe -version` 确认退出码 0 再怀疑成片；两种情况都建议换完整版 ffmpeg / ffprobe 构建。
