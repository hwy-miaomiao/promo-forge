# 需求问询

> **什么时候读这一篇**：走到 **阶段 2 · 需求问询** 时读，也就是阶段 1 预调研做完、还没建项目之前。
> 这一篇只解决一件事——用最少的问题、最少的轮次，把「做什么片子」定死到可以开工的程度。

## 0. 这一阶段的铁律

- 一轮 **5~8 题**，**最多两轮**问完。第三轮开始就是在浪费用户耐心，宁可自己按推荐项往前推。
- 每题**首项必须是推荐项，且必须写清推荐的理由**（理由要落到产品事实，不是"这样更好看"）。
- 最后一题**永远是**"还有别的偏好吗"。
- 需求确认写完，必须拿到用户明确的一句「准确，开始制作」才允许进阶段 3 建项目。用户说"差不多吧""你先弄"都不算。
- AI 在这一步的唯一职责是把选项和后果摆清楚，**不做审美拍板**。

## 1. 先查，再问

问之前先把能自己查的全查掉，**能查的一律不写进问卷**。查这些地方：

| 来源 | 要拿到的东西 |
| --- | --- |
| 产品官网首页 | 一句话定位、品牌主色、slogan 原文、CTA 按钮文案 |
| 官网定价页 | 有没有免费版、目标客户是企业还是个人 |
| 仓库 README / CHANGELOG | 最近一次大版本更新了什么（这是最好的宣传点） |
| 应用商店页 | 截图风格、评分与评论数、被用户反复提到的一个优点 |
| 社媒主页 / 公众号 | 受众说话的方式、常用词、发帖节奏 |
| 已有物料（旧视频、发布会 PPT） | 视觉基调、已有的 Logo 与字体 |

查完写成一页纸结论放进 `调研笔记.md`：**它解决什么问题、谁在用、最值得炫耀的 3 个点、有没有现成界面截图**。
后面所有问题的选项都从这一页纸里长出来。

### 从产品反推问题

产品的类型决定了哪几题最要紧，不要把八道题平均用力：

| 产品类型 | 最要紧的题 | 原因 |
| --- | --- | --- |
| 桌面 / Web SaaS | 界面密度、要不要出现真实数据 | 界面信息量大，竖屏裁切方式必须先定 |
| 手机 App | 要不要手机壳、录屏还是截图 | 决定素材获取方式 |
| 开源项目 | 面向开发者还是普通用户 | 决定术语浓度与可信度来源 |
| 硬件 / 实物 | 有没有实拍素材 | 最怕用渲染图冒充真机 |
| 课程 / 知识付费 | 讲师是否出镜、有无学员反馈 | 可信度靠人和证言 |
| 线下活动 | 时间地点是否已定、票务链接 | CTA 必须是可点的事实 |

## 2. 八个必问项（题库与默认答案）

下面八项是硬性必问清单，缺一项就不算问完。写问卷时按这个顺序排，把最影响工作量的放前面。

| # | 必问项 | 推荐项（默认） | 推荐理由怎么写 |
| --- | --- | --- | --- |
| 1 | 画幅 | **竖屏 9:16（1080×1920）** | 目标平台的信息流以竖屏为主，横版在竖屏信息流里上下留黑边，实际可视面积只有约 1/3 |
| 2 | 时长 | **45 秒 ±10** | 45 秒能装下"痛点 + 3 个功能点 + 蒙太奇 + CTA"四段结构；低于 35 秒讲不清三个功能，高于 60 秒完播率掉得快 |
| 3 | 发布平台 | 目标平台写 1~2 个主投放 | 平台决定安全区（右侧互动按钮）与片尾 CTA 形态 |
| 4 | 目标受众 | 一句话：**谁、在什么场景下、为什么要看** | 受众决定术语浓度、字体重量和语速 |
| 5 | 风格方向 | 见第 3 节，给 3~4 个差异大的选项 | 风格要从产品受众推导，禁止直接默认深色科技风 |
| 6 | 开场方式 | 痛点提问式开场（≤2.0 秒出钩子） | 成本最低、最容易被看懂；悬念式对产品认知要求高 |
| 7 | 配音音色 | 男声偏科技/工具选 `zh-CN-YunxiNeural`，女声偏生活/教育选 `zh-CN-XiaoxiaoNeural` | 音色要和受众的日常收听习惯一致 |
| 8 | 素材来源与版权边界 | 用户提供一手素材优先，其次本仓库脚本截真实页面 | 版权边界要问死：能不能用客户 Logo、能不能出现真人脸、能不能用用户评论 |

补充几个**可选但很值钱**的小问题（有余量就塞进 5~8 题里）：

- 片尾 CTA 要说什么？下载 / 注册 / 预约 / 扫码，只能选一个。
- 品牌名和网址分别怎么读？（中文名 + 英文域名混排最容易读错）
- 有没有**绝对不能出现**的竞品名或数据？
- 发布前是否需要给法务/市场审核（决定要不要留未确认标注）？

## 3. 风格方向怎么问

不要问"你想要什么风格"，这句话拿不到可执行答案。正确做法是**给 3~4 个差异明显的方向，每个方向配一张同尺寸样帧**（1080×1920 或等比缩略），让用户直接看"这个风格用在我的产品上是什么样"。生成方法与选项库见 `references/风格方向.md`。

问卷里这样写：

```text
5. 风格方向（首项为推荐）
   A. 真实界面实录 + 极简白文字层【推荐】——理由：你的用户是企业财务，界面上有大量表格，
      极简白能让表格数字自己说话，不被背景图案干扰。
   B. 杂志排版风——理由：强调专业感，但表格截图会被切碎，需要更多包装镜头。
   C. 手绘白板风——理由：亲和力强，但和"财务合规"的调性偏冲突，建议留给后续科普片。
   附件：sample-A.jpg / sample-B.jpg / sample-C.jpg（均为 1080×1920）
```

三个方向的样帧尺寸必须一致，否则用户会被尺寸差异带跑，挑的不是风格而是清晰度。

## 4. 「抢先看 / 未发布产品」类需求

涉及未发布的产品、未公开的功能、内测中的界面时，**必须在全片标注「未经官方确认」**。做法固定为：

1. 成片**每一个画面**常驻一行小字：`抢先看 / 未经官方确认`，字号约为屏上大字的 1/4，不透明度 0.6。
2. 该标注**必须完整落在竖屏安全区内**（上 10%、下 18%、左 6%、右 14%），不能被平台的互动按钮压住。
3. 标注**全程常驻、不可被字幕遮挡**；与品牌名同屏时两者至少留 40 px 间距。
4. 在 `需求确认.md` 的"特殊约定"里写明这条，并注明**依据日期**（例：截至 2026-10-11 的信息，未经官方确认）。
5. 在 `调研笔记.md` 里记下每个未公开事实的来源与获取时间，方便发布后核对。

未发布产品的片子还要额外确认两件事：**能不能出现真实数据**（截图里的数字要不要打码）、**能不能出现合作方 Logo**。

## 5. 问卷写法模板

```markdown
## 第 1 轮需求确认（共 8 题，每题首项为推荐，可直接回"A/B/C"或写序号）

1. 画幅：A. 竖屏 9:16 1080×1920【推荐，理由：…】 B. 横版 16:9 C. 竖横都出（工作量 ×1.4）
2. 时长：A. 45 秒【推荐，理由：…】 B. 30 秒 C. 60 秒
3. 主投平台：A. 抖音 + 小红书 B. 视频号 C. 官网首页自动播放
4. 目标受众：A.（我根据官网推断的画像，请确认或修正）
5. 风格方向：A/B/C（附 3 张样帧）
6. 开场方式：A. 痛点提问 B. 结果前置 C. 悬念
7. 配音音色：A. 云希（男，偏科技）B. 晓晓（女，偏生活）C. 先给我试听两条再定
8. 还有别的偏好吗？（不能出现的内容、必须出现的画面、审核要求…）
```

第 8 题永远保留，它经常是用户唯一主动说出硬约束的地方。

## 6. `需求确认.md` 模板

阶段 2 结束、阶段 3 建项目时，把下面这份直接写进 `<输出目录>/需求确认.md`。
它是**改版的判定依据**：阶段 11 里任何一条用户意见都要挂回这张表。

```markdown
# 需求确认 · <产品名>

- slug：`acme-app`
- 确认时间：2026-10-11
- 状态：**已确认**（用户原话："准确，开始制作"）
- 对应规范：promo-forge `AGENTS.md` 阶段 2

## 1. 产品一句话

<产品名> 是一个 <品类>，帮 <谁> 在 <场景> 里 <达成什么>。官网原文："……"

## 2. 目标受众

- 是谁：<职业 / 身份>
- 场景：<在什么设备上、什么时间看这条片子>
- 他们最在意：<一个具体指标，例如"月底对账不出错">
- 不要对他们说：<忌用词，例如"赋能""闭环">

## 3. 平台与画幅

| 项 | 决定 | 依据 |
| --- | --- | --- |
| 主投平台 | 抖音 / 小红书 | 用户回答第 3 题 |
| 画幅 | 9:16 | `timing.json` 的 `aspect` = "9:16" |
| 分辨率 | 1080×1920 @ 60fps | `timing.json` 的 `width/height/fps` |
| 安全区 | 上 10% / 下 18% / 左 6% / 右 14% | AGENTS.md 第 4 节 |

## 4. 时长

- 目标时长：**45 秒**（`timing.json` 的 `duration`，必须等于最后一个场景的 `end`）
- 场景表（首尾相接、不留缝）：

| 场景 | start | end | 内容 |
| --- | --- | --- | --- |
| hook | 0.0 | 4.5 | 痛点开场 |
| demo | 4.5 | 26.0 | 三个真实界面 |
| proof | 26.0 | 36.0 | 真实作品蒙太奇（≥6 张） |
| cta | 36.0 | 45.0 | 品牌 + 网址 |

## 5. 风格与样帧选择

- 选定方向：A 真实界面实录 + 极简白文字层
- 样帧文件：`sample-A.jpg`（1080×1920），对比样帧 `sample-B.jpg` / `sample-C.jpg`
- 用户原话："就 A，B 那个太花了"
- 配色：bg `#FFFFFF` / fg `#111111` / accent `#2F6FEB`（写入 `timing.json` 的 `brand.colors`）

## 6. 开场方式

- 方式：痛点提问式
- 钩子文案（≤13 字/行）："对账又要熬到半夜？"
- 约束：开场 ≤2.0 秒内出现痛点或亮点；第一次能量爆发最晚在第 4 秒完成

## 7. 配音音色

- 引擎：edge（免费）｜音色：`zh-CN-YunxiNeural`｜语速：`+8%`
- 试听记录：用户听过 `preview-01.mp3` / `preview-02.mp3`，选了 01
- 语速按 5.5~6.5 字/秒写稿；超时先删字，最多加速 12%

## 8. 素材清单与授权

| 文件 | 类型 | 来源 | 授权 / 边界 | 用在哪 |
| --- | --- | --- | --- | --- |
| shots/dashboard@2x.png | 真实界面截图 | capture.py 自截 | 自有产品 | demo |
| brand/logo.svg | 品牌资产 | 官网下载 | 用户确认可用 | cta |

- 一手素材优先：用户提供 > 真实页面截图 > AI 生成图 > 网络图片
- 真实素材配额：片长 ≤45 秒全片 ≥6 张；>45 秒 ≥8 张；蒙太奇段 ≥6 张
- 完整逐张清单（含授权条款与署名要求）写在 `调研笔记.md`，见 `references/素材与截图.md`

## 9. 特殊约定

- 未发布功能标注：全片常驻"未经官方确认"小字（截至 2026-10-11）
- 禁止出现：<竞品名 / 未授权数据 / 真人脸>
- 审核要求：发布前需市场部过一遍，预留 1 轮改版

## 10. 修改记录

| 轮次 | 日期 | 用户意见（原话） | 影响范围 | 处理方式 | 状态 |
| --- | --- | --- | --- | --- | --- |
| R1 | 2026-10-13 | "第二段太快了，没看清" | demo 场景节奏 | 关键镜头拉到 ≥1.2 秒，重渲 | 已完成 |
```

## 7. 哪些问题不该问

| 不该问 | 为什么 | 自己做 |
| --- | --- | --- |
| "你们官网是什么" | 一搜就有 | 阶段 1 预调研 |
| "数据是真的吗" | 截图里能看出来 | 用真实截图，别编数 |
| "背景音乐喜欢哪首" | AI 不能替你听，也不该让用户空手选 | 剪 15 秒片段、统一到 -14 LUFS、叠人声后再让他听 |
| "这个功能要不要放" | 从"3 个最值得炫耀的点"里能推 | 按配额决定（每段至少 1 张真实截图） |
| "用什么字体 / 颜色" | 从品牌资产和风格方向推 | 写进样帧让用户看结果 |
| "要不要加字幕" | 默认就是要加 | `captions.enabled = true`，单行 ≤13 字 |

**判据很简单**：这个问题的答案，用户答错会导致返工吗？不会的，就不要问。

## 8. 用户说"你来决定"

这是常见回答，处理方式固定三步：

1. **选推荐项，不选最花哨的**。推荐项的判据只有一条：它对应用户最初那句话里最想传达的东西。
2. **把理由写进 `需求确认.md`**，格式是"决定 + 依据 + 影响"。例：
   > 决定：竖屏 9:16。依据：主投抖音信息流。影响：所有场景按相对单位布局；横版不在本轮交付范围。
3. **给一次反悔窗口**：明确告诉用户"这三项我按推荐项定死了，你随时可以说改，改一项要重跑哪些步骤"（改版影响范围见 AGENTS.md 阶段 11 的表）。

"你来决定"不等于"免确认"。**仍然需要用户回复一句「准确，开始制作」**，这是阶段 2 唯一的放行信号。

## 9. 收尾自查（进入阶段 3 之前逐条打勾）

- [ ] 八个必问项全部有明确答案，没有"待定"
- [ ] 每题首项都是带理由的推荐项，最后一题是"还有别的偏好吗"
- [ ] 3~4 张样帧已生成，尺寸一致，用户已选定其中一个
- [ ] 首轮提问数在 5~8 之间，总轮次 ≤2
- [ ] `需求确认.md` 十节齐全，含修改记录表（哪怕是空表）
- [ ] 目标时长落进 30~60 秒，且等于场景表最后一个 `end`
- [ ] 真实素材配额已经承诺（≤45 秒 ≥6 张；>45 秒 ≥8 张；蒙太奇 ≥6 张）
- [ ] 未发布产品已写明"未经官方确认"标注与依据日期
