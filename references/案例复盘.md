# 案例复盘

> **什么时候读这一篇**：**开工前读一遍**，用它校准时长分配、素材配额和判断"这个坑大概什么时候会出现"。

⚠️ **本文件里的五个项目都是虚构的**（名称、数据、用户原话均为写作需要构造），只用来演示方法。**只学方法与数值取向，不要照抄任何一支片子的风格与配色**——照抄风格正是 AGENTS.md 第 4 条总原则明令禁止的事。每个项目的风格都必须从它自己的受众和调性推导。

下面每个案例都按同一结构写：产品与受众 / 风格选择及理由 / 结构与时间轴 / 踩到的坑 / 用户修改意见原文与处理 / 可复用结论。

---

## 案例一 · SaaS 工具「票据猫」· 45 秒

**产品与受众**：把纸质票据拍照转成可入账数据的小工具，付费方是小微企业主和兼职会计。一句话卖点是"拍一张，自动进表"。

**风格选择及理由**：**杂志排版 + 真实界面实录**。选它是因为受众每天看表格和报表，对"漂亮插画"无感、对"能不能对上账"极敏感；杂志排版能承载较高的信息密度且不需要花哨动效，真实截图正好是这支片子最有力的证据。配色定为深墨绿底 + 纸张米白 + 单一琥珀强调色——票据和纸张的联想直接来自产品本身，而不是从"科技感"套路里挑的。字体：正文用无衬线黑体栈，数字用等宽字体（金额对齐）。

**结构与时间轴**（`duration` = 45，四段首尾相接）：

| 场景 | 时间 | 时长 | 内容 | 关键约束 |
| --- | --- | --- | --- | --- |
| hook | 0.0–4.0 | 4.0s | 手写凭证堆成山 + "月底对账三天" | 第一次爆发落在 **2.9s** |
| demo | 4.0–21.0 | 17.0s | 拍照 → 识别 → 一键导出，三个真实界面 | 每段 ≥3.0s，第三段进蒙太奇 |
| montage | 21.0–29.0 | 8.0s | **7 张**真实作品（各类票据 + 导出后的表格） | 快切 **0.6~0.9s**，卡 beat |
| cta | 29.0–45.0 | 16.0s | 品牌 + 网址 + 试用入口 | CTA 停留 ≥2.5s，放在能量最高处 |

`music`：`beat` 0.4615、`bar` 1.846、`drop` 2.9；实拍截图 9 张（>6 张达标）。

**踩到的坑**
1. 首版把 drop 定在 3.6s，用户反馈"开头太温"，**最晚第 4 秒要完成第一次爆发**卡着线过。把首句砍到 7 字后 drop 提到 2.9s，首次爆发提前了 0.7s。
2. `mix.py --env` 打印包络发现 demo 段人声只比音乐高 **4.2 dB**（要求 ≥6 dB），在 `timing.json` 里把 `duckDb` 调到 `-9.0` 重跑混音才过。
3. 字幕出现一行 19 字，超出**竖屏单行 ≤13 字**，删成"三张报表，一键出"（9 字）。
4. 手机上抽帧发现导出按钮被平台右侧按钮区压住，把 CTA 整体左移，**右侧 14% 不放任何内容**。

**用户修改意见原文与处理**
- 「演示段像在教我点鼠标，我想看到结果，不想看过程。」→ 保留"点击 → 结果"两拍，但每拍只留"结果"画面 ≥1.2s，按键动作全删；demo 从 22s 压到 17s。
- 「网址再给我多留一会儿，我发给客户看。」→ cta 场景从 9s 延长到 16s，网址停留 6.5s，新增"扫码试用"一屏，但**同一版式没有连用超过 2 次**。
- 「背景那个绿色能不能再压暗一点，手机上有点扎眼。」→ 只改 `timing.json` 的 `brand.colors.bg`，重渲，没有动组件。

**可复用结论**：45 秒的默认时长对"工具类产品"是舒服的，但结构占比要偏 demo；CTA 给到 12~16 秒（占全片 27%~35%）对"要发给客户看"的场景明显更好。

## 案例二 · 开源项目「DeepFlow」· 40 秒

**产品与受众**：一个 Python 数据管道框架，受众是能看懂代码的工程师。他们对"动画包出来的假界面"容忍度极低，对 benchmark 和 diff 极其敏感。

**风格选择及理由**：**真实界面实录 + 纯文字卡点**。因为这支片子的第一原则是可信度：终端和编辑器**只有实录**能说服工程师。刻意**不用**深色科技风的那种氛围光晕与圆角卡片——本项目的风格表把"深色科技风"列为**禁止当默认答案**的那一种，只有在产品本身确实是深色开发者工具时才允许，且要给出理由。配色为深底 + 青绿强调（终端里本来就有的颜色），字体全部等宽，不做花哨字效。

**结构与时间轴**（`duration` = 40）：

| 场景 | 时间 | 时长 | 内容 | 关键约束 |
| --- | --- | --- | --- | --- |
| hook | 0.0–3.5 | 3.5s | 三行日志报错 → 一行命令修复 | 第一次爆发 **2.6s** |
| demo | 3.5–13.5 | 10.0s | 真实 benchmark 与 diff，两屏 | 信息型场景 ≥3.0s |
| montage | 13.5–21.5 | 8.0s | **6 张**真实截图（issue / PR / 文档 / 星标曲线） | 每张 ≥0.5s |
| proof | 21.5–30.0 | 8.5s | 两位真实贡献者的 issue 原话 | 第二次爆发 ~20.4s |
| cta | 30.0–40.0 | 10.0s | 仓库地址 + `pip install` | 停留 ≥2.5s |

**踩到的坑**
1. 第一首曲子算出来**节拍一致性 0.86**（后半段是自由节奏的钢琴，没有稳定鼓点），低于 **0.9** 的门槛。没有硬修，直接换曲，换后 0.93。
2. 一开始想录终端滚屏做成 40 秒，"技术感"最足，但竖屏里一屏只能放 8 行、字号小于 24px 就不可读；改成"diff 左右分栏 + 三行关键日志"，可读性立刻上去。
3. `调研笔记.md` 里 benchmark 数字抄错一位（1.9× 写成 2.4×），抽帧审图时对上官网才抓出来——**所有数字必须回原始页面核对，并在笔记里记出处与日期**。
4. 星标曲线截图是 1 倍图，推近就糊，重跑 `capture.py --factor 2`（1080 宽显示需要 2160 像素）。

**用户修改意见原文与处理**
- 「B 站观众很多是静音看的，字幕得能独立看懂。」→ 逐句改写 `voice.lines`：每句都能脱离画面单独成句（"一行命令，三种数据源"），并在 montage 段补 6 个小标题。
- 「不要放我们的 roadmap，那是内部计划。」→ 删除该镜头，换成已发布版本的 changelog 截图；发布范围只写已经公开的事实。

**可复用结论**：开源项目只要素材够、节拍稳，40 秒完全成立；给工程师看的片子，**真实截图的数量比风格华丽度重要一个量级**，蒙太奇放 issue / PR / 文档同样算真实素材。

## 案例三 · 效率 App「番茄岛」· 50 秒

**产品与受众**：手机端时间管理 App，受众是 22~35 岁的上班族与自由职业者，付费意愿来自"我总在加班，但说不清时间花哪了"。

**风格选择及理由**：**实拍质感 + 强调色**（人物手部特写 + 界面实录交替）。选实拍质感是因为产品卖"省时间"这种感受，记录感比 3D 渲染更可信；同时避开"冷蓝计时器 + 焦虑文案"这个同类产品的常见组合——那套视觉会让观众先感到压力、再关掉视频。配色用暖橙 + 米白 + 深棕文字，字体选圆润的黑体。

**结构与时间轴**（`duration` = 50，素材 **11 张**真实截图 + 3 段用户提供的实拍）：

| 场景 | 时间 | 时长 | 内容 | 关键约束 |
| --- | --- | --- | --- | --- |
| hook | 0.0–4.2 | 4.2s | 一句话 + 一个倒计时数字卡点 | 第一次爆发 **3.4s** |
| demo | 4.2–23.5 | 19.3s | 三段真实界面（记录 / 周报 / 提醒） | 每段 ≥3.0s |
| proof | 23.5–35.0 | 11.5s | 测试组对比：平均每日专注时长 | 数字带出处 |
| montage | 35.0–39.5 | 4.5s | **6 张**真实周报截图快切 | 0.75s/张，卡 beat |
| cta | 39.5–50.0 | 10.5s | 品牌 + 网址 + 一年版入口 | 能量最高处 |

**踩到的坑**
1. 中间放了一个品牌 logo 动效转场，只有 0.9s，被自己的节奏表拦下（**纯转场 ≤0.5s** 或按重点镜头 **≥1.2s** 处理，不能卡在中间）。
2. 两个场景用了不同 hex 写强调色，抽帧拼联系表时肉眼看出色差。改成只从 `timing.json` 的 `brand.colors` 取色，组件里禁止硬编码颜色。
3. 音频没有对齐：`drop` 填成了音乐时间，卡点整体偏了 0.7s；按 `musicOffset = drop - downbeat` 重算 `offset` 后对齐。
4. 第二版把 demo 的一个重点镜头压到 1.0s 想"更紧凑"，结果用户看不清界面中的关键数字，改回 **≥1.2s**。

**用户修改意见原文与处理**
- 「C 段有点吵，三个音效一起响。」→ 那 2 秒里删掉 whoosh，只留重拍冲击与 UI 点击，并把 UI 点击相对音量从 -24 dB 再降一档（重拍冲击 -12 dB / whoosh -18 dB / UI 点击 -24 dB 的分层保持不变）。
- 「周报那一段我想让人看清上面的数字。」→ 从快切里去掉，改为一个 3.5s 的信息型场景，框选关键区域。

**可复用结论**：**时长不是靠压缩镜头换来的**——50 秒里有 19s 给 demo 才讲得清；想缩短就该删信息点，而不是把每个镜头都压到 1 秒以下。

## 案例四 · 知识付费课程「夜校 Python」· 55 秒

**产品与受众**：面向在职者的 8 周 Python 入门课，受众 28~40 岁（多为转岗或想提效的非技术岗）。他们已被大量"三天速成"广告教育过，天然不信任夸张承诺。

**风格选择及理由**：**杂志排版**（封面感大标题、色块、细分割线、目录式页码）。课程卖的是信息密度与结构感，排版风格能直接传达"这门课有目录、有章节、有作业"。配色刻意**避开**高饱和洋红 + 亮黄的"卖课风"，改用深蓝 + 哑光砖红。字体：标题用粗黑体，正文黑体栈，页码等宽。

**结构与时间轴**（`duration` = 55，截图 **9 张**真实素材）：

| 场景 | 时间 | 时长 | 内容 | 关键约束 |
| --- | --- | --- | --- | --- |
| hook | 0.0–4.5 | 4.5s | "第 3 次买课，还是没打开" | 第一次爆发 **2.8s** |
| proof | 4.5–15.0 | 10.5s | 学员进度数据（真实可核实） | 数据必须有出处 |
| demo | 15.0–34.0 | 19.0s | 课程页 + 讲义 + 作业页，三段 | 每段 ≥3.0s |
| montage | 34.0–41.0 | 7.0s | **6 张**学员作业截图快切 | 0.9s/张 |
| cta | 41.0–55.0 | 14.0s | 大纲 + 网址 + 开课时间 | 停留 ≥2.5s |

**踩到的坑**
1. 素材不够：真实截图只有 4 张（<8 张，55 秒不达标）。**没有用 AI 图凑数**，而是补录了"讲义页面 / 作业批改页 / 后台数据 / 课程目录页"四张真实截图，凑到 9 张。
2. 初稿文案写"3 天学完 12 章"，属于效果承诺与绝对化表述，直接删掉，改成"前两章平均 42 分钟"这种**中性、可核实**的事实，并在 `调研笔记.md` 写明数据来源日期。
3. 用户想用 AI 生成"学员头像"做证言，属于伪造证言，改成**真实聊天的截图 + 昵称打码 + 时间戳**。
4. 片尾 2 秒里塞了网址、价格、二维码三样东西，全都不达标（CTA 至少 **2.5 秒**）。删掉二维码，价格改成"详情见课程页"。
5. 55 秒跨了 5 个场景，`caption` 停留时长按 **字数/6 + 0.35 秒**（照 5.5~6.5 字/秒的配音语速估，要活到人声读完）重算过一遍，全片有两句需回改文案。

**用户修改意见原文与处理**
- 「强调色太亮，看着像在推销。」→ 饱和度下调两档，改成哑光砖红；同时把大标题字号收一号，让排版透气。
- 「加一句我们的退款政策。」→ 加进 cta 的第二屏，用同一版式（不新增第三种版式），并核对与课程页原文一致。

**可复用结论**：55 秒成立的前提是**素材数量**（≥8 张）和**信息点数量**（≥10 个），不是"把 45 秒的内容拉长"；合规上凡是"效果 / 绝对化"表述一律换成可核实的事实。

## 案例五 · 线下活动「城市咖啡市集」· 35 秒

**产品与受众**：一场周末限定市集，受众是 20~35 岁的城市青年，刷到视频后 3 秒内决定"这周末去哪儿"。

**风格选择及理由**：**黏土 3D 包装 + 实拍**。线下活动的死穴是现场照片普遍不精、天气不可控，所以用黏土风做包装、转场与背景，把画面统一成暖木色 + 奶油 + 薄荷绿的手工感；但**活动本身的信息（摊位、时间、地点、摊位主）全部用真实照片与真实海报**。这正是总原则的分界线：AI 只负责包装，不负责充当事实现场。真实素材 7 张。

**结构与时间轴**（`duration` = 35）：

| 场景 | 时间 | 时长 | 内容 | 关键约束 |
| --- | --- | --- | --- | --- |
| hook | 0.0–3.6 | 3.6s | 黏土咖啡杯 + 日期 + 地点 | 第一次爆发 **3.1s** |
| montage | 3.6–12.0 | 8.4s | **7 张**实拍快切（0.6~1.0s/张） | 必须 ≥6 张 |
| info | 12.0–22.0 | 10.0s | 摊位主 + 地图 + 时间地点 | 信息型场景 ≥3.0s |
| cta | 22.0–35.0 | 13.0s | 报名 + 二维码 | ≥2.5s，第二次爆发 ~21.5s |

**踩到的坑**
1. 想让 AI 生成观众人群当现场镜头——**不允许**，会被误认为真实现场。改成只用 AI 做杯套 / 海报 / 指示牌这类包装物，人物一律真照片。
2. 现场照片是阴天拍的，偏灰。直接拉饱和度出现色偏，最后改用室内摊主特写 + 食物图，问题消失。
3. 蒙太奇一开始只凑了 5 张，**没有达到 ≥6 张**，补拍一次才够。规则是硬性的：数量不够就先补素材。
4. 花字只能写事实："限量 30 份"、"周六 10:00–18:00"能写；"不虚此行"这类主观评价删掉，改成"摊主名单见活动页"。

**用户修改意见原文与处理**
- 「35 秒太短了，能不能加摊位介绍？」→ 不加时长，把 info 段 10s 内部改成"三个摊位轮播"，同一版式只连用 2 次。
- 「二维码太小扫不出来。」→ 放大到画面宽度 42%，居中，右侧 14% 完全留空；抽帧后用手机实扫验证一遍。

**可复用结论**：线下活动可以短到 35 秒，因为它卖的是"一个动作"（报名）；短片的时长下限由 CTA（≥2.5s）和蒙太奇（≥6 张 × ≥0.5s）共同决定。

## 跨案例规律（六条以上，可直接当检查项用）

1. **默认 45 秒是对的，但真正的开关是素材数量。** 素材 9 张以上可以把片子做到 50~55 秒；素材只有 5~6 张时，正确做法是压到 40 秒以内，而不是用 AI 图凑到 45 秒。五个案例的落点：45 / 40 / 50 / 55 / 35 秒。
2. **第一次爆发集中在 2.6~3.4 秒。** AGENTS.md 的底线是"最晚第 4 秒完成第一次爆发"，但在 5 个真实案例里，凡是被用户说"开头温"的，爆发点都在 3.4s 之后。想稳过审，就把第一次爆发压到 **2.8s 左右**，代价是首句必须砍到 7~9 字。
3. **节拍一致性 0.9 是分水岭，但 0.9~0.92 还要人工微调。** 五个案例终稿为 0.91 / 0.93 / 0.92 / 0.94 / 0.90。0.90~0.92 的三支片子都额外花时间微调了 drop 位置；0.93 以上的基本一次过。低于 0.9 不要修，换曲。
4. **用户意见里，内容类占多数，但真正拖交付的是技术口径。** 五个案例共 11 条意见，内容向 7 条、技术向 4 条；而卡住交付时间的反复出现的四件事是：**人声被音乐压（≥6 dB）、字幕单行超 13 字、drop 错位、2 倍图 / `media.py prepare --max 2800` 没做**。
5. **AI 图永远只做包装、转场、背景，不做事实。** 五个案例里出现过的合法用法：黏土包装物、抽象背景、转场元素、纯排版底纹。越界过的两次（伪造学员头像、AI 生成"现场观众"）都被判定必须删改。
6. **时间轴统一按"钩子 → 演示/内容 → 证明 → CTA"四段切，但各段占比随产品类型大幅变化。** 工具/App 的演示段最大（约占 38%）；开源项目的证明段与蒙太奇最重；课程要靠证明段建立可信度；线下活动把蒙太奇提前到片头之后。
7. **交付时一定要把 `需求确认.md` 与 `调研笔记.md` 归档完整。** 五个案例的改版环节 **100% 用到了这两份文档**——用户原话用来判断改动范围，品牌名大小写与数字出处用来防错。这两份文档缺一份，改版就要重新问一遍用户。
8. **改一处要重做多大的范围，是可以提前告诉用户的。** 只改字幕文案（组件 → 重渲）、只换音色（`tts.py` → `mix.py` → 换音轨，画面不重渲）、改配乐（重新分析 → 更新 `beat/bar/drop` → 卡点微调 → 重渲）、换风格（回阶段 2 重出样帧 → 场景大改 → 全流程重跑）。把这四种影响的成本在交付时讲清楚，用户就不会为了一个错别字要求重做整片。
