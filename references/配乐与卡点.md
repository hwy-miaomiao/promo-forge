# 配乐与卡点

> **什么时候读这一篇**：**阶段 5 配乐与卡点** 时读。改配乐（阶段 11）也回到这里重跑一遍。

## 1. 挑曲子的标准

免费可商用曲库很多，但**能用在 45 秒产品片里的不多**。按下面五条筛，一条不过就换下一首：

| 筛选项 | 通过标准 | 为什么 |
| --- | --- | --- |
| BPM | **90~140**（最稳 100~128） | 低于 90 卡点太稀，镜头切换会显得拖；高于 140 拍点比剪辑还快，观众只记得抖 |
| 明显 drop | 前奏后有一个能量陡升点，且**在曲子的 4~16 秒内** | 硬性要求"最晚第 4 秒完成第一次爆发"，drop 太晚就没法用 |
| 结构清楚 | 前奏 / 主歌 / 副歌分段明显，段与段之间有小节边界 | 卡点靠小节，结构糊的曲子只能整段铺 |
| 循环点 | 找得到可无缝循环的 4 或 8 小节 | 45 秒几乎一定要剪接，没有循环点就得硬切 |
| 无人声 | 或有只有气声的 pad | 有唱词会和人声旁白打架，且免费曲库的唱词授权常更窄 |

补充两条：**优先选有 4/4 拍、节奏稳定的曲子**；**避免有突然静音**（会被 `check_video.py` 判成空档）。

## 2. `music.py` 怎么用、怎么读

```bash
python scripts/music.py analyze <file...>                                   # 下载/分析，出 BPM 与整体统计
python scripts/music.py grid <file> [--from --to]                           # 逐拍/逐小节栅格
python scripts/music.py bars <file> --beat --downbeat --offset              # 逐小节能量与爆发点
python scripts/music.py cut <in> <out> --start --dur                        # 剪出片段（试听与剪接都用它）
```

### 四步流程

**第一步：分析候选**

```bash
python scripts/music.py analyze audio-src/music/*.mp3
```

逐个文件看它报出的 **BPM、总时长、有没有检测到明显 drop、有没有突然静音**。BPM 落在 90~140 之外、或没检测到 drop 的，直接淘汰，不要往下走。

**第二步：看栅格，确认拍点是否稳**

```bash
python scripts/music.py grid audio-src/music/track.mp3 --from 0 --to 20
```

输出的每一行是一个拍点（beat），带时间戳与序号。读法：

- **相邻拍点的时间差**应该基本恒定。若输出里出现 0.31、0.62 这种成倍数关系，说明检测把八分音符当成拍了，取大的那个值当 beat。
- 若差值忽大忽小（0.52 / 0.39 / 0.55），说明这首曲子节奏不稳或检测不稳，**换曲**，不要硬修。
- 拍点序号每 4 个一组就是小节。第 1、5、9…拍（每小节第一拍）是候选 downbeat。

**第三步：取 downbeat 与 drop**

从 `grid` 输出里找出**第 4 秒前后、能量明显抬升的那个小节第一拍**，它就是 downbeat（第一个重拍）。`bars` 会直接给逐小节能量，用它在数字上确认：

```bash
python scripts/music.py bars audio-src/music/track.mp3 --beat 0.4615 --downbeat 0.0 --offset 0.0
```

读法（关键，别只看最后一列）：
- **每小节一行**，能量值突然比前一小节高出 1.5 倍以上，通常就是 **drop**。
- **稳定性**：把这一段所有小节能量算出来，去掉最高与最低的一个，看剩下的波动。波动大的曲子不适合当铺垫段，可以只用它爆发后的那 20 秒。
- **一致性**：脚本给出一致性分数，**硬性要求 ≥0.9**。低于 0.9 说明拍点检测与真实听感对不上，**换曲或换 offset 重测**，不要带病往下做。

**第四步：写回 `timing.json`**

```jsonc
"music": {
  "file": "audio/music.wav",
  "source": "audio-src/music/track.mp3",
  "offset": 0.0,        // 视频时间 = 音乐时间 + offset
  "beat": 0.4615,       // 每拍秒数 = 60 / BPM
  "bar": 1.846,         // 每小节秒数（通常 4 beat）
  "drop": 3.69,         // 第一次爆发的视频时间
  "gain": 0.6
}
```

`beat` 与 `bar` 是**秒**，不是 BPM。换算：`beat = 60 / BPM`（130 BPM → 0.4615 秒），`bar = beat × 4`（→ 1.846 秒）。写完之后**整支片子的所有时间都必须从这几个数推**，任何组件里都不许硬编码拍长。

## 3. `musicOffset = drop - downbeat`

这条公式解决"音乐从哪里起播"。含义：**把音乐里那个重拍（downbeat）挪到视频的 drop 时刻**，让全片第一次爆发正好踩在重拍上。

- 视频时间 = 音乐时间 + `offset`
- 希望：音乐时间 `downbeat` 的那一刻，出现在视频时间 `drop`
- 所以：`drop = downbeat + offset`，即 **`offset = drop - downbeat`**

符号最容易记反，记这一句：**offset = 你要的爆发时刻 − 音乐里重拍的时刻**。想让音乐晚点进来填后面的画面，offset 就是正的；想跳过曲子的前奏，offset 就是负的。

三种典型情形：

| 情形 | 数据长什么样 | 算法 | 结果 |
| --- | --- | --- | --- |
| **有前奏** | 曲子 0~2 秒是铺底，第一个重拍在音乐 2.0 秒；要求第 4 秒爆发 | `offset = 4.0 - 2.0` | `offset = +2.0`，音乐从**视频 2.0 秒**起播，**视频前 2 秒没有音乐**——必须补一段 0~2 秒的低能量铺底（前奏原声或同曲的弱段），否则开场是干声，直接不合格 |
| **直接爆发** | 音乐 0 秒就是重拍，drop 定在 3.6 秒 | `offset = 3.6 - 0` | `offset = +3.6`，音乐从视频 3.6 秒起播，前 3.6 秒要另找一段能量更低的素材填，或用同曲的 8 小节做铺底 |
| **跳过前奏** | 曲子前 12 秒都在铺垫，重拍在音乐 12.0 秒；要求第 3.6 秒爆发 | `offset = 3.6 - 12.0` | `offset = -8.4`，从音乐 8.4 秒处开始读，前奏被剪掉——**负 offset 是剪辑，不是延迟** |
| **无鼓点（环境音/氛围）** | 检测不到 drop，能量曲线平缓 | 放弃卡 drop | 把 `drop` 设为全片能量最高点所在时间（通常 CTA 起点），`beat` 按 60/BPM 写，卡点降级为**卡小节**，`offset` 取 `drop - downbeat` 并在 `需求确认.md` 里写明"本片无鼓点，卡点为小节级" |

写进 `timing.json` 的 `drop` **必须是视频时间**，不是音乐时间。这是最常见的错，改完配乐一定要重新核一遍。

## 4. 卡点技巧

**镜头切换落在 beat 还是 bar？**

| 切换类型 | 落在 | 理由 |
| --- | --- | --- |
| 大段落切换（hook → demo → proof → cta） | **bar**（小节线） | 段落感强，用 bar 更"整" |
| 逐条信息、逐项功能点出现 | **beat** | 元素逐个出现间隔要求 ≥0.25 秒，一个 beat（0.46 秒左右）刚好 |
| 快切蒙太奇 | **beat，每 1~2 拍一张** | 快切镜头 ≥0.5 秒，正好约等于 1 拍 |
| 转场特效（划像/whoosh） | beat 前 0.05 秒起 | 让特效的"落点"压在拍上而不是起点 |

**能量表怎么用**：把 `bars` 输出的逐小节能量画成一条曲线（手画或抄成表格都行）。用法三条：

1. **找全片最高点** → CTA 必须放在这里（网址/CTA ≥2.5 秒，且在全片能量最高处）。
2. **找第二、第三高点** → 两次能量爆发（≥2 次）安排在这两处。
3. **找低洼段** → 低能量小节放信息型场景（≥3.0 秒），慢节奏才看得清界面细节。

**必须对齐 drop 的三个时刻**：

1. **第一次爆发**：最晚在第 4 秒完成，必须压在一个重拍/小节线上。
2. **蒙太奇起点**：≥6 张真实作品的快切段起点落在重拍上，第一张切换不能提前。
3. **CTA 起点**：品牌名 + 网址出现的瞬间落在全片能量最高点的小节线。

**禁止**：为了对齐拍点而把关键镜头压到 1.2 秒以下——节奏底线优先于卡点。

## 5. 音效层次

在三层里分配相对音量（以人声为参照，脚本里 `vo_margin` 会保证人声比该处音乐高 ≥6 dB）：

| 层 | 内容 | 相对人声 | 出现时机 |
| --- | --- | --- | --- |
| 重拍冲击（impact / boom） | 掉在 drop 与爆发点上 | 约 -12 dB | 全片 ≤4 次，多了就吵 |
| 转场 whoosh | 划像、推镜、闪白 | 约 -18 dB | 每次转场一次，纯转场镜头 ≤0.5 秒 |
| UI 点击 / 提示音 | 界面按钮被点、卡片出现 | 约 -24 dB | 只在指哪说哪的 demo 段用，一个场景 ≤3 次 |

三条纪律：**音效不能盖住人声的辅音**（"是""四"这类容易糊）；**不使用需要额外授权的音效包**（免费曲库自带的最省事）；**同一音效不在 1 秒内重复**。

## 6. 统一到 -14 LUFS 再给用户试听

**AI 听不到声音，禁止自己拍板选曲。** 流程固定为：剪片段 → 统一响度 → 叠人声 → 交给用户。

```bash
# 1) 每首候选剪同样的 15 秒：从各自 drop 前 3 秒开始
python scripts/music.py cut audio-src/music/track-a.mp3 audio-src/music/preview-a.mp3 --start 1.0 --dur 15

# 2) 用 ffmpeg 统一到 -14 LUFS / 真峰值 -1 dBFS（两遍法：先测量）
ffmpeg -i audio-src/music/preview-a.mp3 -af loudnorm=I=-14:TP=-1.0:LRA=11:print_format=json -f null -
#    把输出里的 measured_I / measured_TP / measured_LRA / measured_thresh / target_offset 填进第二遍：
ffmpeg -i audio-src/music/preview-a.mp3 -af loudnorm=I=-14:TP=-1.0:LRA=11:measured_I=-19.4:measured_TP=-2.1:measured_LRA=6.8:measured_thresh=-30.2:offset=0.6:linear=true -ar 48000 preview-a-14.wav

# 3) 叠上人声（试听片段必须是"最终听感"，不是纯音乐）
ffmpeg -i preview-a-14.wav -i audio-src/vo/01.mp3 -filter_complex "[1:a]volume=1.0[vo];[0:a]volume=-6dB[bg];[vo][bg]amix=inputs=2:duration=longest" -ar 48000 preview-a-mix.wav
```

给用户的话术固定成三句：**"三条候选各 15 秒、响度已统一、都叠了同一句人声；请只选一条，我按你选的写回 timing.json。"**
用户选完，把结果与原话记进 `需求确认.md`；未被选中的候选从 `audio-src/music/` 移走，避免混音时误用。

## 7. 版权注意

- **不要用流行歌、影视配乐、游戏 BGM**，哪怕只用了 3 秒——平台识别极准，会直接下架或静音。
- 免费可商用曲库的常见限制，逐条核对：**不得转售曲子本身**、**要求署名**（多数是"建议署名"或"必须署名"，后者要在片尾留出处）、**不得用于仇恨/政治/成人内容**、**部分曲库限制单条视频的最大曝光量或禁止用于付费广告投放**。
- 曲子的**出处、曲名、曲库名、条款链接、下载日期**全部写进 `调研笔记.md` 的"音乐与音效"表。
- 客户提供的音乐同样要问清授权范围，**"客户给的"不等于"能商用"**。
- 剪接改动了曲子的结构（`music.segments`）不改变授权，但**不得把曲子重新上传到曲库或分发**。

## 8. 自检

- [ ] BPM 落在 90~140，曲内有明确 drop，无突然静音
- [ ] 节拍一致性 **≥0.9**，`grid` 输出的拍间隔恒定
- [ ] `beat = 60/BPM`、`bar = beat × 4`，且 `timing.json` 写的是秒
- [ ] `offset = drop - downbeat`（爆发时刻 − 重拍时刻），`drop` 是**视频时间**
- [ ] 全片 ≥2 次能量爆发，最晚第 4 秒完成第一次，且压在小节线上
- [ ] 蒙太奇起点、CTA 起点对齐能量高点
- [ ] 候选已用 `loudnorm` 统一到 -14 LUFS，叠人声后交给用户选
- [ ] 用户的选曲原话与结论已进 `需求确认.md`，出处与条款已进 `调研笔记.md`
